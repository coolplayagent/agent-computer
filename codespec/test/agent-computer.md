## 运行验收环境

- 本地：一台 Linux amd64 K3s 节点，真实 containerd/runsc/Chromium/Playwright/JuiceFS CSI/PostgreSQL/S3 endpoint。
- 多节点：生产配置的控制面，至少两台可单独断网/停止的执行节点；数据库、对象存储与执行节点故障域分开。
- 受控网站：登录、上传/下载、表单提交、Canvas/视觉定位、iframe、多标签、可查询副作用记录、延迟与重复回执。
- 控制面：两个 API/协调器实例，两套独立客户端，数据库主时钟和可观察的租约/事件日志。
- 人的入口：独立页面、不同 origin 的集成宿主，至少两名 human 与一个 agent；覆盖第三方 Cookie 禁用、登录窗口受限、隐藏标签页、断线及未授权 origin。
- 运行成果：有健康接口和可验证读写的生成 Web 应用、启动失败/超时应用、静态应用、本地 SQLite 状态应用；输入 Artifact 有固定 hash，能在应用侧独立查询每次交互。
- 文件：普通文本、代码、二进制、大对象、Unicode 文件名、恶意路径、符号链接、hardlink、配额边界。
- 故障工具：在确定提交点前后停止进程，暂停数据库连接、阻断 S3、分区节点；所有破坏测试使用一次性环境。
- 记录确切 source commit、镜像 digest、内核/驱动/数据库版本、配置、输入数据、日志、证据 hash 和预期/实际结果。
- 部署：干净集群/云项目、支持锁的远端 state、上一受支持发行包、可终止的安装阶段、GitOps/直接发布两种单一管理模式；离线能力须在实际断网环境验证。
- 场景：模拟个人/共享/临时会话、真实成员/委托与许可服务、可查询副作用的连接器代理、独立证据读取者；包括依赖不可用、旧 revision、超范围委托与代理绕过输入。
- 准入：两个主体/Workspace 的后台批量请求与交互请求、冻结的配额/公平权重/等待预算，独立观察取消与续约通道。
- 评测扩展：固定测试站点/fixture、不同 split 的引用、隔离 verifier 与不可被被测 Agent 修改的验收标准；无生产账号/凭据。此环境用于 T37，不暗示已建训练系统。

fake runtime、mock S3 和状态机单元测试用于开发反馈；不能替代下面要求真实运行边界的证据。

## 独立断言与故障点

1. 用测试网站或业务服务的权威数据库核对最终结果，不以“鼠标事件已发送”通过 T04/T12。
2. 用另一客户端或节点读回对象校验成果，不仅检查上传客户端内存里的 hash。
3. 用真实进程/节点存活证据核对 fencing；Pod 对象消失或 lease row 更新不是充分证据。
4. 在“对象上传完成、元数据事务之前”“事务完成、响应之前”“外部动作完成、receipt 之前”分别终止执行，验证三类不同恢复路径。
5. T14 的验收必须调用真实 workflow 权威接口与当前 lease；伪造已接受结果不验证两端交接。
6. 测试故意构造错误/过期输入，验证拒绝路径；只覆盖正常例子不能支持权限和并发保证。
7. T21 禁用 Agent/Harness/workflow 服务并核对数据库不存在代理生成的 AgentSpec/Task；不能用预先运行的 Agent 掩盖独立使用缺口。
8. T24 用受控应用记录输入接收主体、序号、时间和副作用，证明交接没有控制重叠；仅看到新 lease row 不足以通过。
9. T25–T27 从应用权威数据、远端浏览器进程与网络记录核对运行位置、交互和隔离，并用独立客户端校验原成果 hash、新版本来源和两用户的不同状态；截图正确不足以证明成品可用。

## 发布门槛

- T00 通过只允许称为“设计文档已交付”。
- Runtime preview 必须列明通过、失败和未测项；缺少 T16 不能宣称所选组合可用。
- 首版产品发布要求 T01–T36、T38–T39 必需场景完成，失败路径无未解决阻断，版本清单与测试快照一致；可选 MCP/离线等能力只在对应子项完成后声明支持，未实现不能计作通过。
- 每个生态组合单独执行 T41；团队组合另需 T40，开发/资料参考组合分别另需 T42/T43。未交付适配器或未完成对应实测时明确不支持，不能用核心通过代替组合证据。
- 评测环境扩展单独要求 T37；未启用时 capability 明确 unsupported，不影响已符合范围的核心发行件，也不能据核心通过宣称支持 Agentic RL。
- 性能试验分别记录冷/热启动、连接首帧、帧率/延迟、浏览器动作、提交、控制交接、成品启动、恢复和每个成功流程的资源成本，公开环境、并发、数据规模和样本量。
- 不能为了通过测试取消共享环境、删除跨节点场景、降级隔离或弱化成果一致性；需要改变产品承诺时先修订需求与设计。

## 验收记录格式

未来每轮运行记录 `test_id、status、source_commit、component_digests、environment、input_refs、expected、observed、evidence_refs、limits`。status 为 `passed/failed/blocked/not_run`，blocked/not_run 均不能计为通过。证据可放外部不可变存储，仓库保留报告入口，不提交秘密、数据库或测试环境凭据。

文档校验报告可保存在本地 `.qualitygate/`，其默认行尾规则不覆盖本文件全部要求。发布验证必须结合真实测试证据，而非增加几个匹配实现的空断言。
