# agent-computer 产品定义

版本：设计基线 0.5；日期：2026-10-09；状态：待实现设计。

本文中的“必须”是产品验收要求，不是已实现声明。技术契约见[详细设计](../design/agent-computer.md)，跨产品责任见[生态集成](../design/ecosystem-integration.md)，测试编号见[验收设计](../test/agent-computer.md)。

0.4 根据[superpod 场景审视](agentic-scenarios-and-gaps.md)补充云部署、产品会话绑定、动作约束、事实交接、证据与准入。0.5 根据用户确认补充多 Agent 定位、协作组件边界和可组合集成方案。R01–R31、R33 为首版核心要求；R34–R35 为可选生态组合的交付与验收要求；R32 为后续可选评测扩展，不代表训练平台能力。全部运行能力仍未实现。

## 1. 定义与用户价值

**agent-computer 是面向人和 Agent 的可连接、可交互、可持久化的电脑基础设施。上层产品通过链接或嵌入界面，让用户直接进入 Computer，操作浏览器和应用，与 Agent 接续工作，并使用运行中的成果。**

Computer 有稳定身份，引用持久 Workspace 和可替换的运行实例。用户保留工作成果、配置和检查点，计算资源可在等待期间释放；替换 Agent 或执行节点后，工作可以继续。

面向团队时，agent-computer 提供可共享、可隔离、可接续的电脑环境，并以环境、执行和成果链路连接其它组件。Agent 按任务和权限分组，Computer 按环境和隔离需求分配；采用多对多连接，不固定“一 Agent 一 Computer”，也不要求所有成员共享同一环境。Agent 的模型循环可运行于外部 Harness 或受控托管 Sandbox，使用 Computer 不要求模型进程位于其中。

人和 Agent 都是直接使用者；开发者与平台团队负责集成和部署。人的使用不依赖 Agent、workflow Run 或待办任务：打开授权链接即可进入 Computer，启动应用、浏览网页、操作文件和保存成果。

视觉能力覆盖正在发生的交互和可运行成果。ComputerView 提供实时画面和输入；Artifact 固定成果内容，Presentation 描述如何运行某个成果版本。模型和 Harness 决定 Agent 下一步动作，人可独立操作；Computer 提供真实环境和执行证据。只发出一次点击不代表业务任务完成。

### 用户与购买/采用理由

| 用户 | 需要完成的工作 | 产品提供的价值 |
| --- | --- | --- |
| Agent 应用开发者 | 为研究、编码、办公 Agent 接入网页和代码执行 | 统一环境与动作接口，减少重复构建浏览器、文件和恢复逻辑 |
| 组织内部平台团队 | 为多个应用提供可管理的持久执行环境 | 资源控制、权限、部署、计量和故障恢复 |
| 人，经独立链接或上层产品嵌入接入 | 独立浏览、打开应用、编辑文件、与 Agent 交接、体验成品 | 可直接操作的 ComputerView；同一 Computer 的工作持续存在 |
| Agent，经 Harness 接入 | 操作浏览器、执行工具、提交成果并请求人工协作 | 与人共享对象和权限模型，可观察、接续和恢复 |

首版成功要求演示：人独立连接和操作、链接与嵌入访问同一 Computer、人和 Agent 接续、生成 Web 应用的真实交互、计算释放后恢复，并通过权限、控制冲突及失败路径验收。

## 2. 已确定的产品决策

| 维度 | 首版决策 |
| --- | --- |
| 定位 | 面向集成者的电脑基础设施；人和 Agent 直接使用，交付 API、CLI、ComputerView 和运维界面 |
| 连接入口 | 认证后的稳定链接与嵌入 ComputerView，同一身份、资源与权限语义 |
| 部署 | 同一组织的私有多机 Linux；本地 Linux 使用同构单节点环境 |
| 交互能力 | 浏览器优先，结构化与视觉路径并存；文件界面、Shell 与生成 Web 应用运行 |
| 成果交付 | 固定 Artifact 版本 + Presentation 运行描述 + 受控 GUI 访问；默认隔离试用数据 |
| 模型与规划 | 外部 Harness；可接入现有 Coding Agent 或 relay-teams |
| 团队与环境 | 长期团队、临时任务组属于外部产品/Harness；默认共享工作空间、按需分配 Computer，资源访问另行授权 |
| 协作与通信 | 通用能力首期归 relay-teams 独立模块，模型适配与通信解耦；独立仓库及部署分别按复用与运行需求决定 |
| 生态组合 | 本仓库交付组合配置设计、适配契约和端到端示例；执行与成果关联贯穿各组件，Computer 核心不接管业务任务 |
| 流程系统 | 对接 workflow-cli，不内置业务 SOP/Task DAG |
| 组件形态 | 各 CLI 独立发布；接口适配和兼容矩阵管理集成 |
| 恢复 | 文件、成果和已提交检查点；重建进程并校验真实状态 |
| 首版计算 | Kubernetes API；优先复用合格现有/托管集群，自建参考 K3s；containerd + gVisor Systrap 为首个认证候选，兼容未通过则阻断 |
| 首版存储 | PostgreSQL + S3；JuiceFS 为共享工作目录参考后端；已有 NAS/CephFS 可优先比较但须适配认证，新建私有对象存储参考候选 SeaweedFS，均尚待组合验收 |
| 自动化交付 | 标准 Helm 包、薄部署 CLI、现有集群与新建基础设施路径；状态、管理权、升级恢复和认证范围明确，见 DP01–DP08 |
| 场景治理 | 个人/共享/临时会话绑定、逐跳委托、受控动作许可、版本化环境、事实交接和用途受限证据；外部继续拥有任务/记忆/训练 |

选型经过调度、隔离、数据库、工作文件与对象服务的分层比较，收益、代价、已有 Ceph/NAS 等改选条件和实验门见[计算与存储多维度分析](../decisions/compute-storage-selection.md)。这里是默认实现方向，不表示所有候选已支持或性能已验证。

## 3. 产品边界

### 3.1 本产品拥有的职责

- Computer、Sandbox、Workspace、App、Presentation 与人/Agent 连接的声明和生命周期。
- 稳定连接链接、独立/嵌入 ComputerView、应用切换和人的独立日常操作。
- 真实浏览器观察与操作、进程执行、文件访问和结果保存。
- 修改租约、浏览器控制租约、人工接管、授权与撤权。
- 持久工作目录、候选修改、不可变 Artifact 和应用检查点。
- 执行幂等记录、断线查询、事件补读、取消、未知结果和环境恢复。
- 运行成果的隔离启动、画面与输入、状态保存策略、配额及回收。
- 运维管理界面、资源配额、审计、诊断和基础资源计量。
- 部署预检与认证交付件、资源绑定、环境交接、证据导出和执行准入；基础设施运维仍由部署平台承担。
- 可组合集成方案、版本兼容清单和环境/成果桥接契约；按启用组合单独验收，不将可选 CLI 全部变为核心运行依赖。

### 3.2 外部责任

| 外部能力 | 责任方 | Computer 提供的输入/输出 |
| --- | --- | --- |
| 模型循环、任务分解、业务动作选择 | Harness | 工具能力、观察、动作结果、检查点引用 |
| SOP、任务依赖、业务终态、审批和验收 | workflow-cli | 固定执行结果与成果引用；外部关联 ID |
| 多 Agent 团队、任务组、协作会话、角色与委派 | 集成产品/relay-teams 或其他 Harness | 多对多授权连接、共享或独立环境、事实交接与固定成果；接入 workflow 时分派关联其 Task/attempt，不另建业务终态 |
| 知识检索、长期记忆、文档转换、质量检查 | 独立 CLI | 授权文件/版本与工具执行入口 |
| 集群、数据库、对象存储基础运维 | 部署平台 | 依赖探测、指标、备份契约、恢复手册 |
| 消息、频道、定时/事件触发和主动参与 | 集成产品及外部调度器 | ContextBinding、幂等 start/execute、事件补读；消息引用不授予权限 |
| 业务审批、连接器身份与委托 | 组织策略/身份服务、受信连接器代理 | 核验动作/输入/版本绑定的许可并强制执行受限路径，不从模型文本批准 |
| 数据集、奖励、训练与模型发布 | 外部评测/Agentic RL 平台 | 经授权的环境版本、执行证据和后续可选 episode 接口 |

### 3.3 首版不包含

- 公共多租户 SaaS、支付计费、跨地域双活或任意第三方不可信租户的隔离承诺。
- 匿名公开预览、任意域名绑定、面向公众的应用托管 SLA；首版链接需要身份认证与资源授权。
- 完整 Windows/macOS 桌面、任意原生应用 GUI 和应用商店。
- 进程内存、网络连接或所有浏览器标签页的无损暂停恢复。
- 自动合并任意二进制文件、实时协作文档 CRDT/OT。
- 内置通用 Agent、模型推理服务、业务聊天与通知产品。
- 内置策略训练、权重同步、通用记忆库、完整 A2A 任务服务；AR07 只规划隔离评测环境扩展。
- 将外部网页副作用包装成无条件 exactly-once；恢复不等于重放。

以上为扩展边界，不删除通用 App、Agent、存储和执行后端抽象。Desktop Driver、其他隔离运行时与存储驱动可以后续适配。

## 4. 核心场景

### U1：浏览器资料处理与 Agent 接续

用户创建有 Browser App 和执行能力的 Computer。Agent A 下载资料并提交输入版本，退出。Agent B 接入同一仍在运行的 Computer，读取成果，执行转换或代码处理并提交报告。上层流程检查报告后完成任务。A 退出不销毁浏览器或 Workspace。

### U2：人工登录与视觉操作

Agent 观察到登录页，请求上层产品转人工。用户领取控制权，旧 Agent 动作停止，用户登录并交还。Agent 获取新观察继续操作。凭据和 profile 不作为普通团队成果共享。

### U3：等待期间释放计算

外部流程进入等待审阅；如果人仍在使用或有运行中的成果会话，不自动停止。满足空闲与授权条件后，Computer 排空修改执行、提交检查点并停止计算。收到后续请求后创建新代次、挂载文件并恢复应用检查点。人通过原链接重新进入，Harness 根据当前页面和业务状态继续，不重放旧坐标。

### U4：并行修改与合并

两个 Agent 需要并行修改时使用独立 Sandbox 和候选目录，输入绑定同一已提交版本。第一份提交更新共享指针；第二份收到版本冲突，保留候选。上层选择重新计算、显式合并或保留独立分支。

### U5：外部 SOP 执行

workflow adapter 在有效 attempt 下申请环境、发起执行、捕获成果，再调用 workflow 的结果验收与提交。重连先查询已有 execution，不因丢失 HTTP 响应重复执行。

### U6：人直接连接与使用

用户在集成产品点击 Computer 链接，认证后打开独立 ComputerView，或在原产品内打开嵌入视图；两者连接同一 Computer。无需创建 Agent，用户即可启动被授权的应用、切换浏览器页面、上传下载、编辑和保存文件。停止的 Computer 按授权与预算唤醒，界面展示启动进度和失败原因。

### U7：交互过程与人机接续

用户打开 ComputerView 实时观察 Agent 的页面操作，请求控制并在安全排空后继续工作。用户保存文件或改变页面后交还控制，Agent 从新观察和最新文件状态继续。多个观察者可同时观看，同一 GUI 不能同时接受多方输入；并行操作需独立实例。

### U8：生成成果的运行体验

Agent 提交生成 Web 应用的固定 Artifact 版本并发布 Presentation。用户打开认证成果链接，启动隔离的应用实例，在远程浏览器里使用成品 GUI。默认试用数据与原成果分开；需要保留修改时显式提交新版本。任务已完成不影响人的活动会话，应用停止后成果版本和入口仍保留。

### U9：团队频道与个人事务的环境边界

同一个 Agent 能力在频道和私聊中被调用。可信集成侧解析不同 ContextBinding：频道使用授权共享环境，私人事务使用个人或临时环境。个人账户结果经审阅和显式提交后才分享；频道成员身份不自动授予个人 profile 或连接器权限。成员退出后关闭失效连接并阻止排队动作派发。

### U10：后台职责和多人资源竞争

外部调度器收到定时/依赖事件后，用稳定触发键恢复相应工作，重复投递查询原执行。等待期间按活动保护释放计算；恢复时重新核验权限和未知副作用。多个 Agent 的启动/执行进入有界公平队列，人的交互与撤权/取消控制通道不会被批量任务耗尽。

### U11：跨 Harness 交班、审阅与证据

新 Harness 读取带环境版本、候选 revision、事件水位和 Unknown 清单的 HandoffManifest，再观察当前状态。需要业务许可的动作绑定确切输入和成果版本，变更后旧许可不能复用。外部验收方通过受控 EvidenceBundle 查询真实回执和成果，模型自报成功不代替业务验证。

### U12：隔离评测环境（后续扩展）

Agent 产品团队从固定 fixture 创建独立 episode，对候选 Harness/策略运行 step，并由独立 verifier 读取终态。reset 产生新代次并清除旧可写状态，禁止生产凭据和不可逆外部探索；训练用途须另有授权。环境故障与业务失败分开，Computer 不执行模型训练。

### U13：团队分工与按需分配电脑

长期团队按本次目标组成任务组，默认包含协调、执行和评审角色。协调者可以只使用消息和模型能力，无需 Computer；执行者按需共享或连接多台 Computer。共享 GUI 轮流控制，并行代码修改采用独立 Sandbox/Candidate，不同私人身份采用独立环境与挂载。评审者读取固定成果，集成者显式合并；成员退出或任务组结束不自动删除仍被使用的环境和成果。

### U14：通过 Computer 组合生态能力

集成者选择独立电脑、Agent 团队或持久流程组合，再按需求启用开发工具、资料转换、知识和记忆。两条参考闭环为：并行开发→固定成果→合并与质量检查→业务验收→人使用应用；资料采集→转换与审阅→固定成果→索引→后续 Agent 接续。组件通过公共契约及固定引用相连，缺少必要适配时该组合不可用；可选知识/记忆服务故障不回滚已确认执行，也不阻断人的独立使用。

## 5. 对象与权威性

| 对象 | 产品含义 | 生命周期与权威记录 |
| --- | --- | --- |
| Computer | 对用户稳定的工作环境身份及能力组合 | 控制数据库；独立于 Pod 和 Agent |
| FS/Volume | 可挂载的持久文件字节 | 存储系统；删除必须显式进行 |
| Sandbox | 有隔离、资源和网络约束的执行域 | 控制面期望状态与实际运行实例共同确认 |
| Workspace | 授权协作范围、文件和成果版本 | Computer 服务；跨业务任务长期存在 |
| App | 运行方式、状态、健康及动作能力 | App 定义与实例；首版 Browser 和 WebApplication |
| Principal | 人或 Agent 的授权主体 | 身份服务与 Computer 授权记录；由服务端确定 |
| AgentSpec | Agent 的可实例化定义 | 可选的 Harness 配置；人的连接不需要它 |
| ConnectionSession | 人或 Agent 与 Computer 的实际授权连接 | 有时效、可撤销；不拥有 Computer 生命周期或自动取得控制权 |
| ViewerSession / ComputerView | 画面/输入传输会话 / 人的操作界面 | 从属于授权连接；独立链接与嵌入共用能力，连接状态不等于运行状态 |
| Execution | 一次受控环境操作的持久记录 | Computer；不等于 workflow 业务 Task |
| Artifact | 已提交、固定内容的成果版本 | 不可变字节与已提交清单 |
| Presentation | 固定成果版本及其可运行方式与访问策略 | 引用 Artifact、AppSpec 和预算；运行复用 AppInstance，不承担业务任务状态 |
| Checkpoint | 环境恢复所需的固定状态集合 | 已提交清单，明确可恢复与不可恢复部分 |
| ContextBinding | 外部个人/共享/临时会话到 Computer 资源的绑定 | Computer 保存绑定 revision；外部会话/成员仍由宿主权威维护 |
| EnvironmentVersion / HandoffManifest | 固定环境配置 / 某次交接的可核验事实引用 | 不可变清单；交接注明 observed/checkpointed 和完整性，不自动授予权限 |
| ActionIntent / ApprovalReceipt | 规范化动作意图 / 外部可信许可引用 | 网关核验并关联 execution；业务批准权不转移给模型或沙箱 |
| ExecutionEvidenceBundle | 授权范围内的执行证据包 | 按用途/内容策略生成，保留缺口与外部验收来源，不等同训练数据授权 |
| Team / TaskGroup | 长期成员与能力组织 / 围绕本次目标、依赖和验收的临时参与组 | 外部产品/Harness；不是 Computer 资源对象，不隐式授予环境权限 |
| CollaborationSession | 有范围的协作消息、参与者及接续记录 | relay-teams/Harness；消息收到、处理完成、业务验收分别记录，不等于 ConnectionSession |

人和多个 Agent 可共享同一实际运行环境和文件；首版通过顺序修改、单 GUI 控制者与独立分支控制冲突。在同一可写 Sandbox 内不承诺互相隔离，权限不同或互不信任的参与者必须分配独立 Sandbox。

## 8. 非功能与完成条件

- 正确性：已确认提交不指向缺失对象；旧代次不得更新当前状态；未知不能转换为成功。
- 耐久性：存储依赖健康时，成功提交必须满足数据与元数据的持久确认；不承诺未经故障实验的断电恢复 SLA。
- 兼容性：发布时固定镜像、驱动、API、数据库迁移和依赖版本；不使用浮动 `latest` 作为复现证据。
- 可观测性：关联 caller、Computer、execution、generation、artifact；敏感正文不进入默认日志。
- 性能：测量启动、动作、文件提交、恢复延迟和每个成功流程的资源成本。数值承诺由固定环境基准产生，不在设计阶段虚构。
- 产品阶段完成：首版核心 T01–T36、T38–T39 对应真实运行证据满足发布门槛，可选生态组合按启用范围另需 T40–T43，可选评测扩展另需 T37；本次仅交付 T00 范围的文档设计，不能声明产品已可用。
