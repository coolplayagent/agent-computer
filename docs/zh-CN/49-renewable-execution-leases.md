# 49. 可续期执行租约

新执行准入默认采用 `renewable: true`。原受信任 worker 可以让命令跨过初始 30 秒窗口继续执行，同时保留监督器、双节点 watchdog 和数据库的有界到期约束。`renewable: false` 保留固定期限的 v1 协议。该策略与[后台 lifetime](48-background-execution.md)独立：关闭逻辑连接不会续约。

## 准入与兼容

不可变 binding 固定本次执行的时长上限：命令超时加 30 秒、Computer 启动准入时长及 3,630,000 毫秒三者的最小值。派发时再用原凭据到期时间约束绝对硬期限；connection lifetime 还受会话到期时间约束。队列和启动准备继续使用原期限，调度、重连、恢复及客户端写租约续期均不能延长它。这是单次执行的时长上限，不代表完整 Computer 激活或空闲生命周期已经实现。

迁移 29 保留旧 input、binding、启动和派发摘要。缺少执行租约策略的已有记录继续固定期限，包括历史 Queued 请求。新请求省略 `renewable` 时，序列化仍省略该字段，策略只加入新记录的不可变 binding。省略、显式 true 和显式 false 是不同的重试输入。响应中的布尔值表示准入策略，不证明控制器仍活着。

v2 bootstrap 和启动 grant 将硬预算绑定到摘要中；v1 字段和 hash domain 保持原序列化。恢复记录不能重建派发 attempt、attach 通道、活 guard 或完成 seal。

## 续约事务与通道

PID 1 在当前窗口约三分之一处、至多十秒后发出新的随机 nonce 和递增序号，计时锚点位于发出之前。同时只允许一个有界 challenge。v2 使用持续打开的认证 v5 attach 通道。收到 challenge 本身不会延长期限。

1. Store 检查原活 attempt、双 guard、原凭据/scope、资源 grant、catalog、Candidate、epoch 和当前期限，为精确启动 grant、challenge 和节点命令提交不可变授权及 Outbox 事件。单独授权不延长数据库或 writer 期限。
2. 原活节点句柄向两个原 watchdog 发送相同命令。每个 watchdog 检查旧计时器尚未到期、序号递增、请求身份一致，以及扩展未超过原硬上限；持久化回执后才确认。原活 reaper 实例还必须确认两个精确日志回执。
3. 第二个 Store 事务重新检查权限和旧期限，原子提交双回执、Outbox 及 writer 到期时间。延迟约束拒绝越过旧期限的提交，也拒绝遗漏 writer 更新。随后 worker 才能在旧 attach 期限之前向 PID 1 发送响应。

每次响应至多授权 30 秒窗口。各时钟域独立使用原先保守计算的硬上限截断该窗口。较早 challenge 或授权锚点之后的延迟会消耗预算，收包不重新开始计时。重放、跳号、跨执行、未知字段、过大或过期帧均拒绝。部分或被取消的写入使通道失效，不盲目重发，也不能恢复已过期租约。

## 独立终止与不确定结果

watchdog 原子重设 Linux `CLOCK_BOOTTIME` 计时器，并检查系统调用返回的旧计时器剩余时间。若重设跨过旧到期点，立即进入终止流程。控制 IO 非阻塞，单独的有界日志线程承担文件写入和 `fsync`，日志卡住不会阻塞 cgroup 终止路径。

reaper 使用绑定原 root 私有日志及不可变逐序号记录的最新有效续约。缺失或不可读的续约证据回退到原期限；与日志发布并发时可能保守地提前终止。该观察不能重建活 worker，也不续约。

确认丢失或第二个 Store 事务失败时，某 watchdog 可能已接受新数据库授权的窗口。数据库仍保留旧的已确认期限，物理监督受最后已授权的节点窗口约束。部分确认使活节点适配器关闭两个控制通道，worker 关闭 IO fence，结果保持不确定；不能据此重试命令。控制器或数据库失联不能维持无限执行。

输出 manifest 和最终报告绑定已接受的序号与 grant 摘要。接受成功/失败还要求原活进程/IO seal 及精确已确认续约回执。陈旧报告、未确认节点扩展或恢复出的日志元数据不能把 Unknown 提升为成功。显式取消、撤权和硬到期继续遵守已有排空与完成规则。

## 验证范围

契约测试覆盖 v1 序列化、严格 v2 通道、锚定到期、不可变策略、WAL 恢复、双确认和事务回滚。显式临时 VM 夹具包括断开连接后运行超过 30 秒、续约后取消/撤权/控制器退出、授权/确认事务失败，以及硬到期。root 节点夹具还冻结私有日志文件系统，独立检查持久化卡住时的终止。[固定源码记录](../evidence/renewable-execution-leases-2026-10-10.json)和[运行日志](../evidence/renewable-execution-leases-2026-10-10.log)保留 451 项 Cargo 测试、15 个 Bazel 目标、25 个真实执行场景及八个节点续约场景的通过证据。长命令断连后完成四次续约；独立 SQL 核验 13 次授权和 12 次确认，包含故意失败的第二次确认事务。单独回读验证 48 个 S3 引用、22 次认证输出下载和十个 Candidate 文件。取证后已移除本次 VM 及私有状态。早期夹具失败和最终仅注释变化的源码差异均明确保留。

范围仍是节点本地 Candidate 执行链路。完整 Computer 生命周期调度、自动排空恢复、多节点 fencing、输出流、浏览器、ComputerView 和产品验收仍待实现。Computer `ready=false`，公开 `execution` 仍不支持，T01–T43 保持 `not_run`。
